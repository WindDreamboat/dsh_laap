# dsh-laap 开发文档

> LAAP 意识认知架构 × DeepSeek Harness 插件 —— 设计、实现与演进路线

## 1. 项目定位

把 [LAAP（Living Agent Application Protocol）](https://blog.csdn.net/2601_95417945/article/details/162627437)的**意识认知内核**移植为 dsh（DeepSeek Harness）的二级插件 Bundle，让任何运行 dsh 的 Agent 获得：

| LAAP 原始能力 | dsh-laap 实现 | 所在层 / 挂载接缝 |
|---|---|---|
| 意识引擎：五维状态向量（压力/信心/好奇/连接/能量）+ 微分方程演化 | `ConsciousnessEngine`（欧拉积分 + 稳态基线回归） | 内核 `core/consciousness` |
| PSI 五需求驱动（确定性/胜任感/自主性/归属感/能量） | `drives()` 剥夺向量 + EMA 需求满足度 | 内核 `core/consciousness` |
| 情绪 = 需求满足率微分信号 | `emotion()` valence/perNeed | 内核 `core/consciousness` |
| 全局工作空间（GWT）/ CognitiveBus | `CognitiveBus` 显著性竞争 → `ConsciousnessFrame` 广播 | 内核总线 + 适配器 prompt（systemPrompt.context） |
| 四层元认知（L1 监控 / L2 控制） | `MetacognitiveMonitor` 贝叶斯置信度校准 + 六档模式选择器 | 内核 monitor + 适配器 tools（laap_state/laap_reflect） |
| 五层记忆（工作/情景/语义/程序/向量） | 工作记忆环形缓冲（7±2）+ **zvec** 情景层/语义层/程序层 | 内核 `MemoryPort`（zvec MemoryLayer）+ 适配器 tools |
| Qualia 内部表征格式 | `qualia()` 体验标记（如「好奇-求偿」） | 意识帧字段 |
| 自我模型（涌现式） | semantic 记忆层的「我是什么样」沉淀（自传自动蒸馏 + 主动记忆） | 内核蒸馏 + 适配器 tools.laap_remember |

## 2. 可行性结论（Step 1 调研摘要）

**结论：可行，且契合度高。** 依据三点：

1. **认知内核是轻量数值系统**。LAAP 公开资料表明纯认知核心（PSI+自我模型+RSI+安全+技能）内存占用约 2.5MB、单步认知循环约 0.07ms（来源：LAAP 架构实用价值，官方知识库 2026-08）——完全可以在 dsh 插件进程内用 TypeScript 重实现，无需 Python sidecar。
2. **dsh「一切皆插件」架构提供了准确接缝**。经核对 `@deepseek-ai/cordis@4.0.2`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-session` 的真实 `.d.ts`：工具注册（`ctx.tools.register(defineTool(...))`）、动态提示词（`systemPrompt.section/context` 支持每次组装时求值的 provider）、事件流（`session/event`、`tools/result`）、资源生命周期（`ctx.effect`）全部公开可用，不需要改 agent-loop。
3. **zvec 是嵌入式（in-process）向量库**，与 dsh 插件同进程模型天然匹配；其 Node.js SDK（`@zvec/zvec`，npm 实测 v0.7.1）提供 `ZVecCreateAndOpen / insertSync / querySync(带标量 filter 下推) / WAL 持久化`，已在本地完成建库→写入→ANN 召回→`kind` 过滤的闭环实测。

### 关键风险与对策

| 风险 | 实测情况 | 对策 |
|---|---|---|
| zvec 依赖 mmap，网络文件系统（OSS/NFS）上会 Bus error | ✅ 实测复现（工作区 OSS 挂载上 SIGBUS） | 默认库路径改本地盘 `~/.dsh-laap/`，文档显式警告 |
| 哈希袋嵌入语义精度弱于真 embedding 模型 | 定性判断 | `EmbedAsyncFn` 可插拔，后续注入外部 embedding API（已支持 OpenAI 兼容/ollama） |
| dsh 处于 RC 版本（0.1.2-rc.1），API 可能变动 | 版本实测 | 全部事件/接口名以安装版本 `.d.ts` 为准，已逐文件核对 |
| 自我指涉回路（laap 工具结果再触发 tools/result） | 设计期识别 | hooks 中跳过 `laap_*` 前缀工具 |

## 3. 技术栈（Step 2）

- **语言/运行时**：TypeScript（ESM，`"type": "module"`），Node.js ^22.19 或 ≥24（实测 v24.19.0）
- **插件框架**：`@deepseek-ai/cordis@4.0.2`（Service / Context / effect / 事件系统）
- **工具定义**：`@deepseek-ai/dsh-tools@0.1.2-rc.1` 的 `defineTool`（JSON Schema DSL，参数校验 + canonical output + 纯投影 render）
- **向量库**：`@zvec/zvec@0.7.1`（阿里巴巴通义实验室开源，Apache 2.0；HNSW/标量过滤下推/WAL 崩溃恢复）
- **嵌入**：内置 256 维字符 bigram 哈希袋（零依赖、确定性、适配中文），`EmbedAsyncFn` 可替换（hash/openai/ollama）
- **形态**：Bundle（host 五个子插件：service / tools / hooks / prompt / ui-host，由 `src/adapters/cordis/index.ts` 统一挂载；外加浏览器半区 ui-client 面板），经 `cordis.patch.yml` 唯一入口声明，可整体安装分发
- **架构**：三层（六边形）——`src/core/` 框架无关内核（零 cordis 依赖）+ `src/adapters/cordis/` 平台适配器 + PlatformAdapter 端口依赖注入；内核经 `dsh-laap/core` 子入口导出，可被任意 JS 宿主复用（`createKernel({}, { dbPath })` 即 Node 默认组合）

## 4. 架构与数据流

### 三层结构（六边形 / 适配器 + 依赖注入反转）

依赖箭头**单向指向内核**：内核拥有端口接口，平台层实现端口；内核 `src/core/` 不 import 任何 `@deepseek-ai/*`，可脱离 dsh 独立运行与测试。

```
平台环境（dsh / 未来可扩展 Node 独立服务、其他 Agent 框架）
        │
        ▼ 实现 PlatformAdapter（logger / scheduler / memory 三端口）
┌──────────────────────────────────────────────┐
│ 平台适配器层  src/adapters/cordis/（dsh 唯一实现） │
│  index/service-plugin/service（薄适配器）        │
│  tools（laap_* 工具） hooks（事件→感知）          │
│  prompt（意识流广播） ui-host/ui-client（面板）   │
└───────┬──────────────────────────────┬────────┘
        │ ctx.logger/ctx.effect 适配注入 │ perceive() / report() / uiSnapshot()
        ▼                               ▲
┌──────────────────────────────────────────────┐
│ 核心业务层  src/core/（框架无关，0 框架依赖）      │
│  LaapKernel（createKernel(adapter, opts) 工厂） │
│  ConsciousnessEngine  Ψ'=-k(Ψ-Ψ*)+Σg·evt       │
│  Needs(PSI) → drives → selectMode               │
│  Emotion = dD/dt      Qualia 标记               │
│  MetacognitiveMonitor (L1/L3/L4)                │
│  CognitiveBus ──竞争──► ConsciousnessFrame      │
│  MemoryPort ◄── MemoryLayer(zvec：工作/情景/语义/程序)│
└──────────────────────────────────────────────┘
```

**端口契约边界**（`src/core/ports.ts`）：

- `KernelLogger`（info/warn）、`KernelScheduler`（setInterval 返回清理函数）、`MemoryPort`（remember/recall/listSkills/working/close）——内核运行必需的平台服务，由适配器实现注入；全部可选，缺省为 consoleLogger + 全局 setInterval + zvec MemoryLayer。
- **EventBus 不设端口**：内核内部已有 CognitiveBus（意识总线）；宿主事件（会话/工具回调）在适配层转换后经 `LaapKernel.perceive()` 进入感知流水线。
- **ToolRegistry 不设端口**：`laap_*` 工具是宿主侧的能力投影（dsh 用 `defineTool` + `ctx.tools.register`），工具协议因平台而异，不进入内核契约。
- 嵌入（`EmbedAsyncFn`）是纯函数注入，不是有状态端口。

```
dsh 会话事件流                        模型主动调用
session/event ──┐                  ┌─ laap_state / laap_remember
tools/result ───┤  hooks 转换      ├─ laap_recall / laap_skill
heartbeat ──────┤                  └─ laap_reflect（tools 适配器注册）
                ▼                  ▼
        LaapService（薄适配器，ctx.laap）
                │  委托
                ▼
        LaapKernel.perceive()
        状态演化 → 投稿总线 → 竞争广播意识帧
                │                  │
                ▼                  ▼
   prompt 适配器：systemPrompt   MemoryPort（zvec）
   .context 每轮意识流注入        工作记忆(7±2) 溢出归档情景/语义层
   （durable user-role 快照，回放可见）
```

一次感知的完整回路：事件（dsh 侧由 hooks 转入，或任意宿主直接调用）→ `kernel.perceive()` 演化状态 → 投稿总线 → 竞争广播意识帧 → 帧叙事沉淀工作记忆（溢出降级归档 zvec 情景层）→ dsh 适配器在提示词组装时以第一人称意识流注入模型上下文；浏览器面板经 ui-host 的 RPC 独立频道 `/laap/snapshot` 拉取 `uiSnapshot()` 纯 JSON 渲染。

## 6. 安装与运行（Step 4 挂载验证）

前提：Node ≥22.19（建议 24）、pnpm ≥11.7、dsh 可用（`npx @deepseek-ai/dsh web`）。

```bash
# 开发期：临时挂载（不污染 Profile）
pnpm dsh web --patch /绝对路径/dsh-laap/cordis.patch.yml

# 发布前：安装到 Profile
dsh plugin --profile web add link:/绝对路径/dsh-laap

# 排查加载
dsh --profile web --dump-config | grep laap
DEBUG=cordis:* pnpm dsh web
```

环境变量（优先级高于 patch 配置；dsh 宿主自动加载启动目录与 `~/.dsh` 下的 `.env`，`.env` 已 gitignore）：`LAAP_ZVEC_PATH`（默认 `~/.dsh-laap/zvec-memory`，**必须本地盘**）、`LAAP_SENSITIVITY`（性格敏感系数）、`LAAP_HEARTBEAT_MS`（心跳间隔）、`LAAP_NOVELTY_THRESHOLD`（新异性阈值）、`LAAP_RECALL_THRESHOLD`（内省召回闸门，0=关；未配时按 provider 自动：hash 关/bge-m3 0.45）、`LAAP_SEMANTIC_DEDUP_THRESHOLD`（语义层去重阈值，0=按 provider 自动：hash 0.92/神经嵌入 0.75）、`LAAP_EMBED_PROVIDER`（hash/openai/ollama）、`LAAP_EMBED_BASE_URL`、`LAAP_EMBED_MODEL`、`LAAP_EMBED_DIMENSION`（换维度必须删旧库重建）、`LAAP_EMBED_API_KEY_ENV`。仓库默认 hash 嵌入，克隆即可离线运行；本地通过 `.env` 切换 ollama/openai，不把个人配置提交进仓库。

模型侧冒烟测试：对话中问「你现在感觉怎么样」，期望模型调用 `laap_state` 并按意识帧回答；连续让工具失败后问它，期望它切换 reflective 并调用 `laap_reflect`。

## 9. 已知限制（诚实清单）

- 意识「动力学」是功能主义最小实现：连续时间被离散化为 tick（事件驱动 + 30s 心跳），非真 ODE 求解器。
- 哈希袋嵌入的语义分辨力有限，短文本近似查询可能排序不稳定（实测召回 top-k 语义方向正确但分数偏低，属正常）。
- 自我报告的意识文本（"我感到好奇"）是**状态向量的叙事投影**，是工程化内感受接口，不是对现象意识的声称。
- 多 Agent scope 隔离：当前内核实例为 dsh 进程全局（每进程一个 LaapKernel）。经调研 dsh 为「一进程 = 一 profile = 一 agent」模型，多 agent 天然按进程隔离；进程内多会话共享连续自我是预期行为，故暂不按 session 拆分（详见第 8 节剩余路线）。
- 浏览器半区只能渲染内核快照（RPC 拉取 JSON）：zvec 是原生 mmap 插件，内核本身不进浏览器；跨宿主复用目前限于 Node 兼容运行时。
