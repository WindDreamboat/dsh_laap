# dsh-laap 开发文档

> LAAP 意识认知架构 × DeepSeek Harness 插件 —— 设计、实现与演进路线

## 1. 项目定位

把 [LAAP（Living Agent Application Protocol）](https://blog.csdn.net/2601_95417945/article/details/162627437)的**意识认知内核**移植为 dsh（DeepSeek Harness）的二级插件 Bundle，让任何运行 dsh 的 Agent 获得：

| LAAP 原始能力 | dsh-laap 实现 | 挂载接缝 |
|---|---|---|
| 意识引擎：五维状态向量（压力/信心/好奇/连接/能量）+ 微分方程演化 | `ConsciousnessEngine`（欧拉积分 + 稳态基线回归） | Service |
| PSI 五需求驱动（确定性/胜任感/自主性/归属感/能量） | `drives()` 剥夺向量 + EMA 需求满足度 | Service |
| 情绪 = 需求满足率微分信号 | `emotion()` valence/perNeed | Service |
| 全局工作空间（GWT）/ CognitiveBus | `CognitiveBus` 显著性竞争 → `ConsciousnessFrame` 广播 | Service + systemPrompt.context |
| 四层元认知（L1 监控 / L2 控制） | `MetacognitiveMonitor` 贝叶斯置信度校准 + 六档模式选择器 | tools + Service |
| 五层记忆（工作/情景/语义/程序/向量） | 工作记忆环形缓冲（7±2）+ **zvec** 情景层/语义层（程序层待完善） | Service + tools |
| Qualia 内部表征格式 | `qualia()` 体验标记（如「好奇-求偿」） | 意识帧字段 |
| 自我模型（涌现式） | semantic 记忆层的「我是什么样」沉淀（最小版） | tools.laap_remember |

## 2. 可行性结论（Step 1 调研摘要）

**结论：可行，且契合度高。** 依据三点：

1. **认知内核是轻量数值系统**。LAAP 公开资料表明纯认知核心（PSI+自我模型+RSI+安全+技能）内存占用约 2.5MB、单步认知循环约 0.07ms（来源：LAAP 架构实用价值，官方知识库 2026-08）——完全可以在 dsh 插件进程内用 TypeScript 重实现，无需 Python sidecar。
2. **dsh「一切皆插件」架构提供了准确接缝**。经核对 `@deepseek-ai/cordis@4.0.2`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-session` 的真实 `.d.ts`：工具注册（`ctx.tools.register(defineTool(...))`）、动态提示词（`systemPrompt.section/context` 支持每次组装时求值的 provider）、事件流（`session/event`、`tools/result`）、资源生命周期（`ctx.effect`）全部公开可用，不需要改 agent-loop。
3. **zvec 是嵌入式（in-process）向量库**，与 dsh 插件同进程模型天然匹配；其 Node.js SDK（`@zvec/zvec`，npm 实测 v0.7.1）提供 `ZVecCreateAndOpen / insertSync / querySync(带标量 filter 下推) / WAL 持久化`，已在本地完成建库→写入→ANN 召回→`kind` 过滤的闭环实测。

### 关键风险与对策

| 风险 | 实测情况 | 对策 |
|---|---|---|
| zvec 依赖 mmap，网络文件系统（OSS/NFS）上会 Bus error | ✅ 实测复现（工作区 OSS 挂载上 SIGBUS） | 默认库路径改本地盘 `~/.dsh-laap/`，文档显式警告 |
| 哈希袋嵌入语义精度弱于真 embedding 模型 | 定性判断 | EmbedFn 接口可插拔，后续注入 dsh LLM 侧或外部 embedding API |
| dsh 处于 RC 版本（0.1.2-rc.1），API 可能变动 | 版本实测 | 全部事件/接口名以安装版本 `.d.ts` 为准，已逐文件核对 |
| 自我指涉回路（laap 工具结果再触发 tools/result） | 设计期识别 | hooks 中跳过 `laap_*` 前缀工具 |

## 3. 技术栈（Step 2）

- **语言/运行时**：TypeScript（ESM，`"type": "module"`），Node.js ^22.19 或 ≥24（实测 v24.19.0）
- **插件框架**：`@deepseek-ai/cordis@4.0.2`（Service / Context / effect / 事件系统）
- **工具定义**：`@deepseek-ai/dsh-tools@0.1.2-rc.1` 的 `defineTool`（JSON Schema DSL，参数校验 + canonical output + 纯投影 render）
- **向量库**：`@zvec/zvec@0.7.1`（阿里巴巴通义实验室开源，Apache 2.0；HNSW/标量过滤下推/WAL 崩溃恢复）
- **嵌入**：内置 256 维字符 bigram 哈希袋（零依赖、确定性、适配中文），`EmbedFn` 接口可替换
- **形态**：Bundle（1 个 Service 类插件 + 3 个函数插件），经 `cordis.patch.yml` 声明，可整体安装分发

## 4. 架构与数据流

```
dsh 会话事件流                        模型主动调用
session/event ──┐                  ┌─ laap_state / laap_remember
tools/result ───┤                  ├─ laap_recall / laap_reflect
heartbeat ──────┤                  │
                ▼                  ▼
        ┌──────────────────────────────┐
        │        LaapService (ctx.laap) │
        │ CognitiveEngine  Ψ'=-k(Ψ-Ψ*)+Σg·evt │
        │ Needs(PSI) → drives → selectMode     │
        │ Emotion = dD/dt      Qualia 标记     │
        │ MetacognitiveMonitor (L1/L2)          │
        │ CognitiveBus ──竞争──► ConsciousnessFrame │
        └───────┬──────────────────┬────────────┘
                ▼                  ▼
   systemPrompt.context      MemoryLayer
   （每轮意识流注入，durable  工作记忆(7±2) + zvec(episodic/semantic)
    user-role 快照，回放可见）
```

一次感知的完整回路：事件 → `perceive()` 演化状态 → 投稿总线 → 竞争广播意识帧 → 帧叙事沉淀工作记忆（溢出降级归档 zvec 情景层）→ 下一轮提示词组装时以第一人称意识流注入模型上下文。

## 6. 安装与运行（Step 4 挂载验证）

前提：Node ≥22.19（建议 24）、pnpm ≥11.7、dsh 可用（`npx @deepseek-ai/dsh web`）。

```bash
# 开发期：临时挂载（不污染 Profile）
pnpm dsh web --patch /绝对路径/dsh-laap/cordis.patch.yml

# 发布前：安装到 Profile
dsh plugin --profile web add link:/绝对路径/dsh-laap

# 排查加载
dsh --profile web --dump-config | grep laap
DEBUG=cordis:* pnpm dsh web
```

环境变量：`LAAP_ZVEC_PATH`（默认 `~/.dsh-laap/zvec-memory`，**必须本地盘**）、`LAAP_SENSITIVITY`（性格敏感系数）、`LAAP_HEARTBEAT_MS`（心跳间隔）。

模型侧冒烟测试：对话中问「你现在感觉怎么样」，期望模型调用 `laap_state` 并按意识帧回答；连续让工具失败后问它，期望它切换 reflective 并调用 `laap_reflect`。

## 7. 验证结果（MVP 已通过）

- **行为验证**：`node --experimental-strip-types test/sim.ts` —— 12 时刻模拟全绿（6/6 断言）：
  状态动力学（失败→压力升至 0.58→自动切 reflective→用户安抚→恢复 deliberate）、zvec 召回排序合理且标量过滤生效、元认知对失败样本打信心折扣（校准 0.90/失败率 67%）、工作记忆有界。
- **静态验证**：`tsc --noEmit` 对 cordis/dsh-tools/dsh-llm/dsh-session 官方类型 **0 错误**。
- **zvec SDK 实测**：建库、insert、ANN 查询、`kind = 'semantic'` 过滤下推、close 全部通过（v0.7.1, Node 24, Linux x64）。

## 9. 已知限制（诚实清单）

- 意识「动力学」是功能主义最小实现：连续时间被离散化为 tick（事件驱动 + 30s 心跳），非真 ODE 求解器。
- 哈希袋嵌入的语义分辨力有限，短文本近似查询可能排序不稳定（实测召回 top-k 语义方向正确但分数偏低，属正常）。
- 自我报告的意识文本（"我感到好奇"）是**状态向量的叙事投影**，是工程化内感受接口，不是对现象意识的声称。
- 多 Agent scope 隔离（dsh-scope）未适配，当前 Service 为进程全局。
